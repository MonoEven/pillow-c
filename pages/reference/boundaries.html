行为边界 · Behavioral Boundaries

pillow-c verifies 2856/2856 behavioral tests and 524/524 DLL exports against a local Pillow 11.3.0. A small set of honest, documented boundaries remain: places where this runtime either fails loudly with Pillow's exact message, or cannot replicate Python-stateful behavior. Everything else is oracle-verified parity — including error messages.

pillow-c 以本机 Pillow 11.3.0 为基准验证了 2856/2856 项行为测试与 524/524 个 DLL 导出。仍保留少量诚实、记录在案的边界:这些位置要么以 Pillow 的原样报错显式失败,要么无法复刻依赖 Python 全局状态的行为。其余一切——包括错误消息——都经过 oracle 逐项验证。

1. 依赖门控格式 · Dependency-gated Formats

WebP / AVIF / JPEG2000

Open and save fail loudly with Pillow image file format is unsupported (save-handler shape) and Pillow's exact decoder webp not available / decoder avif not available / decoder jpeg2000 not available for recognized magic bytes. The local Pillow build ships these codecs; this runtime does not.

打开与保存以 Pillow image file format is unsupported(保存处理器形态)显式失败;对已识别的魔数按 Pillow 原样抛 decoder webp not available / decoder avif not available / decoder jpeg2000 not available。本机 Pillow 自带这些编解码器;本运行时没有。

FPX

Bare KeyError 'FPX' — the deprecated olefile plugin shape is kept verbatim.

裸 KeyError 'FPX' —— 保留已弃用 olefile 插件的原始报错形态。

2. GUI 互操作 · GUI Interop

ImageQt / ImageTk / Show

The runtime ships no Qt binding and no Tk interpreter: ImageQt.ToQImage/ToQPixmap/ImageQt raise Pillow's exact Qt bindings are not installed; ImageTk.PhotoImage raises Too early to create image: no default root window; image.Show() raises the Pillow-shaped no viewers found.

运行时不含 Qt 绑定与 Tk 解释器:ImageQt.ToQImage/ToQPixmap/ImageQt 抛 Pillow 原样的 Qt bindings are not installed;ImageTk.PhotoImage 抛 Too early to create image: no default root window;image.Show() 抛 Pillow 形态的 no viewers found。

3. Python 有状态行为 · Python-stateful Behavior

ImagePalette.Random

Pillow uses Python's global Mersenne-Twister stream. The facade returns palettes with identical shape and value ranges, but the exact stream is unmatchable.

Pillow 使用 Python 全局 Mersenne-Twister 随机流。门面返回形状与取值范围完全相同的调色板,但逐值随机流不可复刻。

ImagePath.Path.Map

The callable Map(fn) returns None without mutating (the AHK None analogue is 0); Pillow's C ImagingTransformHandler form cannot exist in this runtime and stays a documented boundary.

可调用的 Map(fn) 返回 None 且不改动对象(AHK 的 None 对应物为 0);Pillow 的 C 层 ImagingTransformHandler 形态在本运行时无法存在,记为边界。

4. 栅格化与绘制 · Rasterization & Drawing

GDI 字形墨迹 · GDI Glyph Ink

Truetype glyphs are rasterized through GDI: gray8 ink values are the documented rasterizer divergence (outlines/bbox ink do not apply gvar; the HVAR advance-delta engine IS replicated).

Truetype 字形经 GDI 栅格化:gray8 墨迹值为已记录的栅格化差异(轮廓/包围盒墨迹不应用 gvar;HVAR 字宽增量引擎已完整复刻)。

默认字体 · load_default

The bundled default font differs from Pillow's Aileron; default-font metrics match in shape but not byte-for-byte, and default-font drawing uses the native seams.

内置默认字体不同于 Pillow 的 Aileron;默认字体度量形态一致但非逐字节相同,默认字体绘图走原生管线。

Truetype 描边文字 · Stroked Truetype Text

Drawing stroked truetype text raises the facade's exact boundary error Pillow.ImageDraw.Text truetype stroke is not supported by this runtime.

绘制带描边的 truetype 文字抛门面的边界错误 Pillow.ImageDraw.Text truetype stroke is not supported by this runtime。

5. 编码器负载字节 · Encoder Payload Bytes

JPEG 负载字节 · JPEG Payload

JPEG structure, SOF/progressive flags, qtables, DPI and metadata match Pillow; the literal DHT/entropy payload bytes are not byte-identical (documented).

JPEG 结构、SOF/渐进标志、量化表、DPI 与元数据与 Pillow 一致;逐字节的 DHT/熵编码负载不做字节级对齐(已记录)。

GIF 中位切分调色板顺序 · GIF Median-cut Ordering

GIF median-cut palettes cover the same colors; the palette ordering may differ from Pillow's (documented micro-boundary).

GIF 中位切分调色板覆盖同样的颜色;条目顺序可能与 Pillow 不同(已记录的微边界)。

TIFF jpeg / group3 / group4 保存 · TIFF Compression Save

Saving TIFF with compression="jpeg"|"group3"|"group4" raises the documented rejection boundary instead of silently writing a wrong stream.

以 compression="jpeg"|"group3"|"group4" 保存 TIFF 抛已记录的拒绝边界,绝不静默写出错误码流。

PNG 字典 / 压缩 · PNG dictionary / compression

dictionary bytes are accepted-and-ignored (the DLL writes stored deflate blocks — the no-compressor boundary); compress_type 0-4 accepted with Pillow's exact 5+ OSError.

dictionary 字节被接受但忽略(DLL 写 stored deflate 块——无压缩器边界);compress_type 0-4 接受,5 及以上抛 Pillow 原样 OSError。

6. 排版与量化 · Layout & Quantize

无 libraqm · no-libraqm

Text-direction options (direction/features/language) raise Pillow's exact KeyError shape 'setting text direction, language or font features is not supported without libraqm'.

文字方向选项(direction/features/language)抛 Pillow 原样的 KeyError 形态 'setting text direction, language or font features is not supported without libraqm'。

RPN 转 L · ImageMath convert-to-L

The RPN convert("L") seam reports mode I (documented divergence).

RPN 的 convert("L") 报告模式 I(已记录差异)。

量化交叉积 · Quantize cross-products

MEDIANCUT/MAXCOVERAGE/FASTOCTREE and the bounded FLOYDSTEINBERG slices are covered; LIBIMAGEQUANT keeps Pillow's exact dependency required by this method was not enabled at compile time, and ADAPTIVE/none dither cross-products are not byte-exactly replicated.

MEDIANCUT/MAXCOVERAGE/FASTOCTREE 与有界 FLOYDSTEINBERG 切片已覆盖;LIBIMAGEQUANT 保留 Pillow 原样的 dependency required by this method was not enabled at compile time,ADAPTIVE/none 抖动交叉积不做字节级复刻。

7. NumPy 互操作 · NumPy Interop

I;16B 大端 dtype · I;16B big-endian

image.AsArray() on I;16B raises the documented boundary error (Pillow.Image.AsArray: I;16B big-endian dtype (numpy '>u2') is not representable in cnumpy (documented boundary)) — cnumpy ships no big-endian dtype while Pillow's numpy gives >u2. All other dtype/shape mappings are byte-exact against NumPy 1.25.0 + Pillow 11.3.0, including bool 0/255 bytes for mode 1.

I;16B 图像的 image.AsArray() 抛已记录的边界错误(Pillow.Image.AsArray: I;16B big-endian dtype (numpy '>u2') is not representable in cnumpy (documented boundary))——cnumpy 没有大端 dtype,而 Pillow 的 numpy 给出 >u2。其余全部 dtype/shape 映射与 NumPy 1.25.0 + Pillow 11.3.0 逐字节一致,包括 mode 1 的 bool 0/255 字节。

cnumpy 依赖 · cnumpy dependency

The interop is dependency-linked, not hard-wired: without the cnumpy facade included, the APIs raise Pillow numpy interop requires cnumpy (https://github.com/MonoEven/cnumpy): #Include its ahk\numpy.ahk. The interop itself is facade-level (no new DLL exports); FromArray routes through the raw codec seams extended with Pillow's 1;8/I;8/I;16S/F;64F raw modes.

互操作是依赖联动而非硬绑定:未包含 cnumpy 门面时,这些 API 抛出 Pillow numpy interop requires cnumpy (https://github.com/MonoEven/cnumpy): #Include its ahk\numpy.ahk。互操作本身在门面层实现(无新增 DLL 导出);FromArray 走按 Pillow 1;8/I;8/I;16S/F;64F 原始模式扩展的原生原始编解码管线。

8. 其他记录在案的微边界 · Other Micro-boundaries

  • I;16 histogram: Pillow's C path reads 2-byte storage through layout-dependent byte misreads — kept as a documented boundary.I;16 直方图:Pillow 的 C 路径按内存布局误读双字节存储——保留为记录在案的边界。
  • I;16B non-NEAREST resize raises the boundary error (Pillow accepts and garbles via its endian bug; replicating corruption is declined).I;16B 非 NEAREST 缩放抛边界错误(Pillow 接受并因端序缺陷产出乱码;拒绝复刻损坏)。
  • ICO reopen of grayscale PNG payloads: documented WIC boundary (use RGBA sources).ICO 灰度 PNG 负载的重新打开:已记录的 WIC 边界(请用 RGBA 源)。
  • ICNS jp2 payloads keep Pillow's no-jp2 message.ICNS jp2 负载保留 Pillow 的 no-jp2 报错。
  • ImageFile incremental/plugin protocol (Parser, StubImageFile, PyCodec, …) fails loudly on construction with Pillow-shaped messages.ImageFile 增量/插件协议(Parser、StubImageFile、PyCodec……)构造即按 Pillow 形态显式报错。
  • TIFF sub-IFD tags are flattened into the EXIF blob instead of get_ifd() (documented divergence; get_ifd() itself a boundary).TIFF 子 IFD 标签被扁平化进 EXIF 数据块,而非 get_ifd()(已记录差异;get_ifd() 本身为边界)。
  • PNG true compression strategy / APNG: default-deflate single-frame PNGs only (future families).PNG 真实压缩策略 / APNG:仅默认 deflate 单帧 PNG(未来家族)。
