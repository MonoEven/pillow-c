pillow-c — a Pillow-compatible image library for AutoHotkey v2

Welcome to the pillow-c documentation. pillow-c brings a Pillow 11.3.0-compatible image processing API to AutoHotkey v2: a native pillow_c.dll owns image handles, pixel storage and bulk operations, while ahk\pillow.ahk provides the Python-like facade (Pillow.Image, ImageDraw, ImageFont, …). This documentation mirrors the structure of the official Pillow documentation and describes every public API in both English and Chinese.

欢迎阅读 pillow-c 文档。pillow-c 为 AutoHotkey v2 带来了与 Pillow 11.3.0 行为一致的图像处理 API:原生 pillow_c.dll 负责图像句柄、像素存储与批量运算,ahk\pillow.ahk 提供类 Python 的门面(Pillow.Image、ImageDraw、ImageFont……)。本文档仿照 Pillow 官方文档 的结构,以中英双语逐 API 描述全部公开接口。

安装与构建 · Installation & Build

Copy build\x64\Release\pillow_c.dll and ahk\pillow.ahk into your project, then configure the DLL path once:

把 build\x64\Release\pillow_c.dll 与 ahk\pillow.ahk 放进你的工程,然后一次性配置 DLL 路径:

#Requires AutoHotkey v2.0
#Include "ahk\pillow.ahk"

Pillow.Configure({ DllPath: A_ScriptDir "\build\x64\Release\pillow_c.dll" })
img := Pillow.Image.Open("photo.png")   ; 打开 / open
img := img.Resize([800, 600])           ; 调整大小 / resize
img.Save("photo-800.jpg")               ; 另存 / save
img.Close()

To build the DLL from source (Visual Studio 2022, x64 Release):

从源码构建 DLL(Visual Studio 2022,x64 Release):

& 'C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\MSBuild.exe' .\src\pillow_c.vcxproj /p:Configuration=Release /p:Platform=x64 /m

基本概念 · Concepts

Just like Pillow, an image is identified by a mode and a size. Supported modes: 1 (1-bit), L (8-bit grayscale), P (palette), RGB, RGBA, CMYK, YCbCr, LAB, HSV, I (32-bit int), F (32-bit float), I;16/I;16B, and the BGR;/BGR;15/BGR;16/BGR;24 raw variants. The coordinate system has its origin at the upper-left corner: (0, 0) is the top-left pixel, x grows rightward, y grows downward; a 4-tuple box is [left, upper, right, lower].

与 Pillow 一样,图像由 模式 (mode) 与 尺寸 (size) 标识。支持的模式:1(1 位)、L(8 位灰度)、P(调色板)、RGB、RGBA、CMYK、YCbCr、LAB、HSV、I(32 位整数)、F(32 位浮点)、I;16/I;16B,以及 BGR;/BGR;15/BGR;16/BGR;24 原始变体。坐标系原点在左上角:(0, 0) 是左上角像素,x 向右、y 向下增长;四元矩形为 [left, upper, right, lower]。

行为对齐 · Parity

Behavior is verified against a local Pillow 11.3.0 installation (F:\Python\Python310\python.exe) through oracle probes and a full AutoHotkey test suite: 2867/2867 tests passing, 524/524 DLL exports in parity, DLL SHA-256 4B8ABA30335284C99C776B81E0924777A30A644D22BEE6610115C4BC6C4A2481. Every error message, boundary error and conversion rule is pinned against the Python implementation — not just the happy path.

行为以本机 Pillow 11.3.0(F:\Python\Python310\python.exe)为基准,通过 oracle 探针与完整 AutoHotkey 测试套件逐项验证:2867/2867 项测试通过、524/524 个 DLL 导出对齐,DLL SHA-256 4B8ABA30335284C99C776B81E0924777A30A644D22BEE6610115C4BC6C4A2481。每条错误消息、边界报错与转换规则都对照 Python 实现逐一钉死——不止是正常路径。

A small number of honest documented boundaries remain: WebP/AVIF/JPEG2000 decoders, FPX, ImageQt/ImageTk, ImagePalette.random streams and the ImagePath map handler fail loudly with Pillow's exact messages instead of silently diverging.

少量诚实的行为边界被记录在案:WebP/AVIF/JPEG2000 解码器、FPX、ImageQt/ImageTk、ImagePalette.random 随机流与 ImagePath map 处理器——它们以 Pillow 的原始报错显式失败,绝不静默偏离。
