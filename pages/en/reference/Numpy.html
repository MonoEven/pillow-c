Numpy NumPy interop

pillow-c interoperates with cnumpy — the companion NumPy-style native array library for AutoHotkey v2 (v1.21.0-cnumpy, qualified against NumPy 1.25.0). This page mirrors Pillow's Using with NumPy chapter: Image.FromArray is Image.fromarray, and image.AsArray() is numpy.asarray(im). Every dtype/shape rule, byte layout and error message is oracle-verified against local Pillow 11.3.0 + NumPy 1.25.0 (oracle/probe_numpy_interop.py).

Repository reference:cnumpy — https://github.com/MonoEven/cnumpy。The interop requires its facade: #Include "..\2026-07-19-cnumpy-foundation\ahk\numpy.ahk" (or your local cnumpy checkout) before using AsArray/FromArray; without it the facade raises Pillow numpy interop requires cnumpy (https://github.com/MonoEven/cnumpy): #Include its ahk\numpy.ahk.

Image → cnumpy array

AsArray static + method

Pillow.Image.AsArray(image)   ;  numpy.asarray(im) analogue
image.AsArray()               ;  instance form

Returns a cnumpy NdArray over the image's pixel bytes, with numpy's exact dtype and shape. Like Pillow, only pixel values are transferred — a P-mode image loses its palette (indices only). The array is a snapshot copy: it stays valid after the image is closed.

Modecnumpy dtypenumpy dtypeShape

Boundary: I;16B raises the documented boundary error (Pillow.Image.AsArray: I;16B big-endian dtype (numpy '>u2') is not representable in cnumpy (documented boundary)) because cnumpy has no big-endian dtype; Pillow's numpy gives >u2.

cnumpy array → Image

FromArray static

Pillow.Image.FromArray(obj, mode := unset)   ;  Image.fromarray analogue

Creates an image from a cnumpy NdArray, replicating Pillow 11.3.0's fromarray typemap exactly. Without mode, the mode is derived from the dtype and shape; with mode, the bytes are reinterpreted as that raw mode (Pillow's deprecated-mode-parameter behavior, without the deprecation warning).

typestr(dtype / shape)mode / rawmodeNotes
obj
A cnumpy Numpy.NdArray. Non-contiguous (sliced) arrays are serialized in C order first, like numpy's tobytes().
mode
Optional raw mode for byte reinterpretation.

Returns: a new Image.

Parity — exact error shapes (oracle-verified):
• unsupported dtype → Cannot handle this data type: (1, 1[, dims…]), <typestr> (int64/uint64/float16/complex and bad 3-D band counts);
• dimensions → Too many dimensions: {ndim} > {ndmax}. (ndmax: 2 for 1/L/I/P/F, 3 for RGB, 4 otherwise);
• 0-dim arrays → tuple index out of range;1-D arrays become [1, n] images;
• short data under an explicit mode → not enough image data.

Examples

#Include "..\..\2026-07-19-cnumpy-foundation\ahk\numpy.ahk"
Pillow.Configure({ DllPath: A_ScriptDir "\build\x64\Release\pillow_c.dll" })
Numpy.DllPath := A_ScriptDir "\..\..\2026-07-19-cnumpy-foundation\build\x64\Release\cnumpy_ahk.dll"
Numpy.Init()

img := Pillow.Image.Open("photo.jpg")
a := img.AsArray()          ; uint8, [H, W, 3] — numpy.asarray(im)
mean := a.Mean()            ; cnumpy statistics
img.Close()                 ; the array snapshot stays valid

b := Numpy.Zeros([64, 64, 4], 3)     ; uint8 RGBA
im := Pillow.Image.FromArray(b)      ; mode RGBA — Image.fromarray
im.Save("black.png")
im.Close()

Numpy.Cleanup()

Native support: FromArray routes through the raw codec seams (1;8, I;8, I;16S, I;32(S), F;32F, F;64F) added in src/pillow_c_raw.cpp; no AHK per-element loops exist on either path.
