NumPy 互操作 互操作

pillow-c 与 cnumpy 联动——那是配套的 AutoHotkey v2 原生 NumPy 风格数组库(v1.21.0-cnumpy,以 NumPy 1.25.0 为基准)。本页对应 Pillow 的 Using with NumPy 章节:Image.FromArray 即 Image.fromarray,image.AsArray() 即 numpy.asarray(im)。所有 dtype/shape 规则、字节布局与报错文本均以本机 Pillow 11.3.0 + NumPy 1.25.0 为 oracle 逐项验证(oracle/probe_numpy_interop.py)。

互操作需要其门面:#Include "..\2026-07-19-cnumpy-foundation\ahk\numpy.ahk"(或你本地的 cnumpy 检出)后再使用 AsArray/FromArray;缺少时门面抛出 Pillow numpy interop requires cnumpy (https://github.com/MonoEven/cnumpy): #Include its ahk\numpy.ahk。

图像 → cnumpy 数组

AsArray static + method

Pillow.Image.AsArray(image)   ;  numpy.asarray(im) analogue
image.AsArray()               ;  instance form

返回覆盖图像像素字节的 cnumpy NdArray,dtype 与 shape 与 numpy 完全一致。与 Pillow 一样只传输像素值——P 模式图像丢失调色板(只剩索引)。数组为快照副本:图像关闭后仍然有效。

Modecnumpy dtypenumpy dtypeShape
1bool (1)|b1[H, W](字节 0/255,与 numpy.asarray 一致)
L / Puint8 (3)|u1[H, W]
Iint32 (6)<i4[H, W]
Ffloat32 (12)<f4[H, W]
I;16uint16 (5)<u2[H, W]
RGB / YCbCr / LAB / HSVuint8 (3)|u1[H, W, 3]
RGBA / CMYKuint8 (3)|u1[H, W, 4]
LAuint8 (3)|u1[H, W, 2]

边界:I;16B 抛已记录的边界错误(Pillow.Image.AsArray: I;16B big-endian dtype (numpy '>u2') is not representable in cnumpy (documented boundary))——cnumpy 没有大端 dtype;Pillow 的 numpy 会给出 >u2。

cnumpy 数组 → 图像

FromArray static

Pillow.Image.FromArray(obj, mode := unset)   ;  Image.fromarray analogue

由 cnumpy NdArray 创建图像,精确复刻 Pillow 11.3.0 的 fromarray 类型映射。不给 mode 时按 dtype 与 shape 推导模式;给 mode 时按该原始模式重新解读字节(Pillow 已弃用 mode 参数的行为,不含弃用警告)。

typestr(dtype / shape)mode / rawmode说明
|b1,2D1 / 1;8非零 → 255(逐字节输入)。
|u1,2DL / L
|i1I / I;8符号扩展为 int32。
<u2I;16 / I;16直接 16 位存储(Pillow 11.3 的实际结果模式)。
<i2I / I;16S符号扩展为 int32。
<u4 / <i4I / I;32, I;32S
<f4 / <f8F / F;32F, F;64Ff8 把 double 转为 float32。
|u1,(…, 2)LA / LA
|u1,(…, 3)RGB / RGB
|u1,(…, 4)RGBA / RGBA
obj
cnumpy 的 Numpy.NdArray。非连续(切片)数组先按 C 序序列化,同 numpy 的 tobytes()。
mode
可选:字节重解读所用的原始模式。

返回:新 Image。

对齐——精确报错形态(oracle 验证):
• 不支持的 dtype → Cannot handle this data type: (1, 1[, dims…]), <typestr>(int64/uint64/float16/复数与错误的 3D 通道数);
• 维数 → Too many dimensions: {ndim} > {ndmax}.(ndmax:1/L/I/P/F 为 2,RGB 为 3,其余为 4);
• 0 维数组 → tuple index out of range;1 维数组生成 [1, n] 图像;
• 显式 mode 下数据不足 → not enough image data。

示例

#Include "..\..\2026-07-19-cnumpy-foundation\ahk\numpy.ahk"
Pillow.Configure({ DllPath: A_ScriptDir "\build\x64\Release\pillow_c.dll" })
Numpy.DllPath := A_ScriptDir "\..\..\2026-07-19-cnumpy-foundation\build\x64\Release\cnumpy_ahk.dll"
Numpy.Init()

; numpy.asarray(im):像素数组(快照副本)
img := Pillow.Image.Open("photo.jpg")
a := img.AsArray()          ; uint8,[H, W, 3]
mean := a.Mean()            ; cnumpy 统计
img.Close()                 ; 数组仍可用

; Image.fromarray:数组 → 图像
b := Numpy.Zeros([64, 64, 4], 3)     ; uint8 RGBA
im := Pillow.Image.FromArray(b)      ; mode RGBA
im.Save("black.png")
im.Close()

Numpy.Cleanup()

原生支撑:FromArray 走原始编解码管线(src/pillow_c_raw.cpp 新增的 1;8、I;8、I;16S、I;32(S)、F;32F、F;64F);两条路径都没有 AHK 逐元素循环。
