ImageFile 模块

Pillow 11.3.0 的 PIL.ImageFile 模块表面。原生 ABI 整体解码/编码文件,因此增量馈送/插件协议(Parser 基于解码器的路径、StubImageFile、StubHandler、PyCodec、PyDecoder、PyEncoder)属于已记录的行为边界。常量(MAXBLOCK/SAFEBLOCK/ERRORS)、LOAD_TRUNCATED_IMAGES 默认值、整文件 Parser 回退路径以及普通对象 PyCodecState 均已精确覆盖。

常量

MAXBLOCK / SAFEBLOCK constants

Pillow.ImageFile.MAXBLOCK := 65536
Pillow.ImageFile.SAFEBLOCK := 1048576

Pillow 图像 I/O 的默认分块大小,与 PIL.ImageFile.MAXBLOCK、PIL.ImageFile.SAFEBLOCK 完全一致:MAXBLOCK 为单次读取块上限,SAFEBLOCK 是编解码器未声明自身块大小时使用的保守回退值。

ERRORS Map

static ERRORS := Map(
    -1, "image buffer overrun error",
    -2, "decoding error",
    -3, "unknown error",
    -8, "bad configuration",
    -9, "out of memory error"
)

负错误码 → 消息对照表,与源码中的定义完全一致。它镜像 PIL.ImageFile.ERRORS:以下各行是原生 ABI 能够暴露的错误码;Pillow 的该表即是在解码器返回失败码时使用的“负错误码 → 人类可读消息”映射。

截断加载

LOAD_TRUNCATED_IMAGES property

static LoadTruncatedImages {
    get => Pillow.ImageFile._LoadTruncated
    set {
        if value
            throw Error("Pillow.ImageFile.LOAD_TRUNCATED_IMAGES truncated-load tolerance is not supported: native decoders require complete files (the Pillow default is False)", -1)
        Pillow.ImageFile._LoadTruncated := false
    }
}
static _LoadTruncated := false

读写属性,默认 false,与 Pillow 默认一致。将其设为 true 是已记录的显式失败边界:原生解码器严格整体解码文件,无法提供截断容忍,故抛出 Pillow 原样的拒绝消息。

边界:读回始终为 false;赋真值即抛出。见行为边界。

编解码状态

PyCodecState class

class PyCodecState {
    Xsize := 0
    Ysize := 0
    Xoff := 0
    Yoff := 0
}

Pillow 11.3.0 的普通编解码状态对象:四个整数字段,均默认 0。AHK 大小写不敏感使 snake_case 读写(xsize/ysize/xoff/yoff)直接映射到 PascalCase 字段。

Xsize / Ysize
解码后图像的宽高。
Xoff / Yoff
解码目标内的偏移。

边界存根

Pillow 的增量/插件协议无法建立在整文件原生 ABI 之上。这些类在构造时即以 Pillow 形态显式报错,绝不构造惰性空壳。

ImageFile (base object) class

__New(args*) => Pillow.ImageFile.RequireIncremental()

Pillow 的 ImageFile.ImageFile(fp, name) 基对象。AHK 运行时没有文件对象/增量协议,故构造即显式失败。

抛出:Pillow.ImageFile incremental decoding is not supported: the native ABI decodes whole files。见行为边界。

Parser class

parser := Pillow.ImageFile.Parser()
parser.Reset()
parser.Feed(data)
parser.Close()

Pillow 11.3.0 的 ImageFile.Parser feed/close 消费器。门面实现了 Pillow 面向非增量格式的回退路径:累积馈送缓冲区,并在 Close() 时经急切的 Open 重开整条数据流。可观察的 feed/close/error 表面与 Pillow 一致。

Reset
Pillow 断言解析器尚未收集数据;复用抛 cannot reuse parsers。
Feed
追加缓冲区并尝试急切开图,吞掉“尚不可识别”的失败。
Close
重开累积数据流并返回 Image;不可解析的数据抛 cannot parse this image。

边界:基于解码器的增量解码路径仍为已记录的子边界——门面仅走整文件回退路径。见行为边界。

PyCodec / PyDecoder / PyEncoder classes

class PyCodec {
    __New(args*) => Pillow.ImageFile.RequirePyCodecMode()
}

class PyDecoder {
    __New(args*) => Pillow.ImageFile.RequirePyCodecMode()
}

class PyEncoder {
    __New(args*) => Pillow.ImageFile.RequirePyCodecMode()
}

Pillow 11.3.0 的编解码基类。PyCodec.__init__() 需要 mode 参数,因此在缺少它时构造这三者之一都会抛出原样的缺失位置参数错误。

原样抛出:PyCodec.__init__() missing 1 required positional argument: 'mode'。见行为边界。

弃用辅助

ReportOSError static

Pillow.ImageFile.ReportOSError(code)

服务于 Pillow 11.3.0 已弃用的 raise_oserror 辅助(Pillow 12 移除),后者仅翻译编解码器 decode() 返回码——该角色由原生 ABI 直接暴露。以 Raise 开头的 AHK 标识符在调用处会被词法解析为 raise 关键字,名为 error 的参数会遮蔽 Error 类(AHK 名称大小写不敏感),因此门面成员命名为 ReportOSError(code)。

抛出:raise_oserror is a deprecated Pillow helper; codec errors surface directly from the native ABI。见行为边界。

Pillow 11.3.0 中不存在 ImageFileFormat(模块内无此名称),因此本门面也不提供该成员。
